## AMD-06 — Dependency Edge Correction

**Closes:** CMP-BLOCK-014 · **Change class:** metadata correction, two edits

### Defect

`framework.manifest.json` encoded a mutual **build-order** dependency between a law and the agent contract:

| File id | `depends_on` before |
|---|---|
| `LAW-11` | `["laws-index", "agent-contract"]` |
| `agent-contract` | `["LAW-11", "LAW-12", "precedence"]` |

This forms the cycle `LAW-11 → agent-contract → LAW-11`, violating manifest invariant **MI-2** (*the dependency graph is acyclic*) and failing **V-02**, a BLOCKING check.

### Root cause

LAW-11 (Agent Conduct) and `AGENT-CONTRACT.md` legitimately cite one another in prose. That **documentation** relationship was encoded as a **build-order** dependency in both directions. `depends_on` expresses emission order; it does not express citation.

### Correction

| File id | `depends_on` after | `referenced_by` after |
|---|---|---|
| `LAW-11` | `["laws-index"]` | `["agent-contract"]` |
| `agent-contract` | *(unchanged)* `["LAW-11", "LAW-12", "precedence"]` | *(unchanged)* `["agents-index"]` |

**Direction retained is the correct one.** Laws are rank-4 authority and foundational; the agent contract derives from them. Every other law in the manifest depends only on `laws-index` and, where applicable, other laws or `precedence`. `LAW-11` was the sole outlier. The corrected form restores consistency with all twelve sibling laws.

### Semantic preservation

The documentation relationship is preserved in full by an added reference edge:

```
dependencies.edges  +=  { "from": "LAW-11", "to": "agent-contract", "type": "references" }
```

Both directions now exist as `references` edges. **No documentation link is lost.** The rendered files `LAW-11_agent_conduct.md` and `AGENT-CONTRACT.md` are unaffected — they already cite each other correctly, and neither is regenerated by this amendment.

## AMD-07 — Edge Type Semantics

**Closes:** CMP-BLOCK-014 (recurrence prevention) · **Change class:** clarifying ruling, no data change

The manifest defines four edge types but never stated which constrain build order. The compiler inferred the distinction correctly; this amendment makes it explicit so the defect cannot recur.

| Edge type | Meaning | Must be acyclic |
|---|---|---|
| `files[].depends_on` | Emission order — the target must exist before the source is emitted | **YES** |
| `emits` | Producer to product | **YES** |
| `references` | Documentation citation | **No** — cross-references are naturally mutual |
| `reads` | Runtime access | **No** |
| `validates` | Verification target | **No** |

**Ruling:** V-02 acyclicity applies to the **build-order graph** — `depends_on` plus `emits` edges. Reference, read and validation edges are excluded and may be cyclic by design.

**Post-correction state:** 130 build edges, **0 cycles**, topological sort succeeds over all 105 nodes. 20 reference edges, cycles permitted.

## AMD-08 — `ENGINEERING.md` Placement

**Directed action, separate from CMP-BLOCK-014** · **Change class:** placement ruling

### Requirement

`ENGINEERING.md` shall be the canonical human and session entry point, shall duplicate no canonical content, and **shall remain valid regardless of future framework upgrades.**

### Analysis

The upgrade-durability requirement is decisive. Partition upgrade semantics are:

| Partition | Upgrade semantics | Survives upgrade |
|---|---|---|
| `root` (`.ai/`) | replaced-wholesale | **No** |
| `core` | replaced-wholesale | **No** |
| `profile` | replaced-wholesale | **No** |
| `project` | never-touched | Yes |
| `adapters` | merged-additively | Partially |

Placing `ENGINEERING.md` anywhere inside `.ai/` root or `core/` would **destroy it on the first framework upgrade** — directly violating the stated requirement. It would additionally become an undeclared file in an integrity-verified partition, failing V-03a and V-12.

### Ruling

> **`ENGINEERING.md` is placed at the repository root, outside `.ai/` entirely.**

| Property | Consequence |
|---|---|
| Outside every framework partition | No upgrade can touch it, by construction |
| Not a framework artifact | Correctly absent from `framework.manifest.json`; V-03a unaffected |
| Project-scope, not framework-scope | It indexes the whole repository, of which `.ai/` is one part |
| Not an authority | It is an index. Where it disagrees with a canonical artifact, **the canonical artifact governs.** |

**The manifest is not amended.** `ENGINEERING.md` is a project artifact; `framework.manifest.json` governs `.ai/**` only.
