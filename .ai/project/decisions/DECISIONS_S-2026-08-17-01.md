## DEC-11 — `C-4`: the repository license

**Question.** `LICENSE` has been an explicit placeholder since Release 0.1 preparation, stating
that until resolved *"all rights are reserved"* and *"Do not publish this repository publicly
until this placeholder is resolved."* The owner's instruction authorises a public push.

**Governing sources.** The owner's 2026-08-17 delegation, which names license selection
expressly; `SEDEP-PMP-002` §1, which records a *proposed* dual-license intent; LAW-01 and
LAW-10, which govern what a per-file notice would do to a registered artifact.

**What was established rather than assumed.** Every third-party license was read from the
installed distribution's own metadata: `jsonschema` MIT, `pytest` MIT, `tiktoken` MIT,
`sentencepiece` Apache-2.0, `matplotlib` PSF-style permissive; transitive dependencies MIT,
Apache-2.0, BSD-3-Clause, Zlib, 0BSD, CC0-1.0. **Nothing in the set is copyleft**, so no
obligation propagates inward. No third-party source is vendored. The Autodesk Fusion API is
imported by `fusion_addin/**` and no Autodesk code is reproduced.

**Alternatives.**

| | Verdict |
|---|---|
| **A — MIT (code) + CC-BY-4.0 (documents, engineering artifacts, generated design data), boundary by path** | **SELECTED** |
| B — MIT throughout | Rejected. MIT's warranty and notice language is written for software and reads poorly over a frozen engineering baseline, drawings and BOMs |
| C — Apache-2.0 throughout | Rejected on a technical ground, not a preference — see below |
| D — proprietary / all rights reserved | Rejected. It contradicts the owner's instruction to push publicly |
| E — add CERN-OHL-P-2.0 for the hardware artifacts | Considered seriously and rejected: a third path boundary through `cad/**` and `drawings/**` for no gain, since CC-BY-4.0 already permits manufacture without restriction. A boundary a reader can get wrong is a defect in a repository whose premise is that authority is path-determined |

**The decisive reason, and it is technical.** **No per-file license header may be added to this
repository.** Roughly a hundred artifacts under `spec/**`, `framework/**` and `.ai/**` are
hash-registered under DC-1 in `FROZEN.md` and `core/MANIFEST.lock`. Inserting a header into any
one of them moves its digest, voids the approval bound to it under LAW-10 clause 2, and halts
boot step B2a. A license that must be satisfied by one root file was therefore required. MIT
and CC-BY-4.0 both are; Apache-2.0 recommends per-file notices, which is why C was rejected.

**Selected: A.** `LICENSE` rewritten: the boundary by path, exhaustive over the tracked tree;
the full MIT text; the full CC BY 4.0 legal code embedded verbatim, retrieved from
`creativecommons.org/licenses/by/4.0/legalcode.txt` so the license survives without a network.
`LICENSE` §3 states expressly that **no patent and no trademark license is granted** — worth
saying plainly for an electrostatic chuck pedestal in a densely patented field — and that the
design is **not qualified hardware**, with 91 of 137 requirements needing an article that does
not exist.

**Recorded limitation.** The copyright holder is named by the identity of record in the
repository — the git author of every commit and the owner of the remote. No legal name is
declared anywhere in the tree and **one was not invented**. `LICENSE` §4 records this and the
owner may substitute a legal or corporate name without any other change.

**`C-4` is closed.** Its second, unregistered instance — `metadata.license` in the frozen
manifest — is closed with it at DEC-15.

## DEC-12 — `ECR-D-015`: the deliverables were not in the repository

**Question.** `cad/DELIVERABLES.md` declared the export root *"outside this repository by
rule"*. Which rule?

**Answer: none.** `SEDEP-PMP-002` §3.1 directs *"STEP exported at each gate, **committed to
`cad/exports/step/`**"*; §3 marks the Fusion export root **`[Generated — mirrored to repo]`*`;
§1 declares `cad/exports/{step,stl}` and `drawings/{parts,assembly}`; and `.gitignore` carried
`!cad/exports/step/*.step` and `!drawings/**/*.pdf` negations with nothing to negate.

**Consequence, which is what makes it a defect rather than a preference.** A clone contained a
register of 62 digests naming files on one machine at an absolute `D:` path. Every provenance
claim was unverifiable by anyone but its author. A digest register whose subjects are
unreachable proves nothing and looks as though it does.

**Selected: A — mirror 61 of 62 in, byte-identical.** The exclusion is `*.f3d`, the parametric
source, which the same plan assigns to Fusion cloud versioning. Byte identity proven twice:
SHA-256 before and after the copy, and again by materialising the git index into a clean
directory with `git checkout-index` and re-comparing — 62 of 62 identical.

**One consequence was not optional.** `.gitattributes` declares `* text eol=lf` over every
path and its own comment says *"There is no binary content to damage. **Re-run that check
before adding any.**"* It was re-run: **14 PDF and 10 STL carry NUL octets and are not UTF-8**;
the other 37 are UTF-8 with CRLF. Under the blanket rule git would have corrupted the binaries
and rewritten the rest, **moving every one of the 61 recorded digests**. The four deliverable
subtrees are declared `-text`, scoped by path and never by extension so the 69 `.json` and one
`.csv` elsewhere stay where they belong.

**Standing check built:** `python -m aief_deliverables`, bi-directional, 12 adversarial tests.
The register was true and unreachable for four sessions because nothing bound it to anything.

## DEC-13 — `ECR-D-016`: the Support Ring isolation joint does not close

**This is the engineering finding of the run, and it was found by doing owed work.**
`OI-C-15` §6.2 recorded that the `SR-03`/`SR-04` creepage and clearance traces had never been
filed. Filing them found three frozen acceptance criteria failing on frozen dimensions.

**One omission produces all three.** `spec/03` §2.1 computes the stray capacitance across
*"the 14 mm vacuum gap"* and §3.1 computes the `SR-04` clearance as *"the open annular gap
between the clamp ring and the Cooling Plate = 14 mm"*. Both treat the gap as empty. §5.2 puts
`SEWCP-401`, a **6.00 mm** grounded ring, inside it, seated 0.50 into the `SR-IF-2` register.
**5.50 mm of the 14.00 mm gap is grounded metal.**

| | Required | Computed |
|---|---|---|
| `SR-04` clearance | ≥ 12.00 mm | **8.50 mm** — and this is the *greatest* value achievable under any hardware, since it places the RF-hot boundary flush with the ceramic |
| `SR-03` creepage | ≥ 20.00 mm | **14.00 mm** as modelled, 17.42 with the fillets the model omits |
| `SR-02` shunt impedance | ≥ 400 Ω | **353.9 Ω** |

**The arithmetic is proven against the specification's own published answer.** Fed §2.1's own
14 mm gap, the model returns §2.1's own 17.4 pF, 9.6 pF and 435 Ω to the digit. The control
passes and the substitution fails, so the divergence is in the input.

**Two further findings, independent of every number above.** `SEWCP-401` at Ø318.0/Ø286.0 seats
on the face the Ø300.0/Ø294.0 web rises from — a 3.00 mm radial collision, and it cannot be
re-shaped because it must carry the Ø302 BC taps, which is where the web is, and the bolt
circle is pinned by `FBA-3`. And the flange offers 16.00 mm of radial width against 16.00 mm
of demand from its own frozen features — **zero margin before any edge distance**, which is why
`SR-D12`, `SR-D15`, `SR-D16` and `SR-D21` are absent from the verified model. The omission is
the geometric conflict manifesting, not a modelling slip (`OI-CAD-04`).

**Alternatives, each rejected on computed grounds** (full arithmetic at the ECR): thin the
clamp ring (cannot carry 8 × 2.5–3.5 kN of preload; leaves the collision and the creepage
shortfall); relax all three requirements (`SR-04` → 8.50 is defensible on `spec/08` `RF-09`'s
own vacuum-side precedent with `DR-11` in force, but `SR-03` cannot follow — halving creepage
removes FMEA row 3's stated mitigation against the mechanism it was written for); tap the
frozen Base Plate (breaks `FBA-3` and the `DR-1` firewall); raise the web to 26.5 mm
(`R_web` 0.316 K/W against `SR-05`'s 0.20 ± 0.03, and ring height 20.000 → 32.5 breaks `DR-3`).

**Selected: A — Rev B baseline revision. Ruled here; implemented at Rev B.**

**Why the implementation is deferred, and why that is not an evasion.** It re-opens a frozen
specification volume, invalidates a verified CAD model together with its drawing and its
exports, moves the assembly, and needs an independent QA round of its own. Executing a
re-baseline inside a release-preparation session would be reckless, and doing it hastily to
turn a criterion green is the failure this repository exists to prevent. **A feasible Rev B was
computed and published** so the next authority meets arithmetic rather than a blank page:
discrete flange lugs, web outboard of the bolt circle, both fastener stacks recessed —
≈0.207 K/W, ≈532 Ω, 14.00 mm clearance, ≈22 mm creepage, all four requirements closing.

**`SEWCP` hardware build is BLOCKED until Rev B.** No gate, no deliverable and no repository
release is blocked: the disposition satisfies `C7` and `aief_gate` exits 0.

## DEC-18 — release scoping: what `CMP-BLOCK-004` and `CMP-BLOCK-005` actually gate

**Question.** Both are recorded `Blocking`. Do they block this repository's public release?

**No, and the register says so if read closely.** `CMP-BLOCK-004` gates *"Release 1.0.0"* of
the **AIEF framework** — the full six-stage compiler as software. `CMP-BLOCK-005` gates the
validation-campaign evidence `V-10`/`V-12`/`V-15`/`V-18` for the same. Neither names this
repository, and neither can be discharged by it: both require software that does not exist and
whose construction is a program of work, not a release step.

**Decision: the SEWCP repository releases at `v0.11.0`, not at AIEF 1.0.0.** They are different
releases of different things that happen to share a tree. The framework travels *inside* this
repository as an installed instance at `.ai/`, and its own 1.0.0 is a separate milestone. The
release documentation states this plainly rather than letting a reader infer that a repository
with two blockers is being shipped over them.

**What this decision does not do:** it does not close, weaken or re-scope either blocker. Both
remain open, blocking what they have always blocked.
