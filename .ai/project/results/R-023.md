## 1 · Why the tests failed, and why that is not a test defect

`OQ-14` reserved Compiler Stage 6 execution to the human owner. The owner authorised it at
`S-2026-08-11-06` and the canonical emission was performed 2026-08-12, so the reservation is
discharged and the item is closed. Three assertions had encoded the *pre-closure* state as a
constant:

| Test | Pinned | Property it was reaching for |
|---|---|---|
| `test_exec_records::test_open_items_parses_and_excludes_closed` | `OQ-14 ∈ open`, `OQ-15 ∉ open` | the parser admits the open sections and excludes `Closed` |
| `test_exec_graph::test_open_item_blocks_stage_six` | `"OQ-14"` in T-006's blocked reasons | a declared, still-open `blocked_by` item is reported as a blocking ground |
| `test_exec_graph::test_blocked_is_derived_not_declared` | the same string, as one of three grounds | the same, as the third independent ground |

**This is the `OI-C-12` defect class exactly** — *"pin a six-task snapshot of live, growing
project state"* — and `R-017` repaired four other instances of it by the same rule: **test the
property, not the snapshot.** Three instances survived that pass because nothing had yet moved
them. `OQ-14`'s closure moved them.

Each now derives its exemplars from the repository:

- the open-items test parses `OPEN_ITEMS.md` section by section and asserts the parser's set
  **equals** the union of the non-`Closed` sections and is disjoint from `Closed`, with two
  vacuity guards so an empty parse cannot pass;
- both graph tests call one helper, `_declared_open_blockers`, which intersects `T-006.blocked_by`
  with the live open set and asserts the intersection is non-empty before using it.
