## Notes

**`LAW-05` is why this task exists as a separate record.** `T-009` raised `ECR-D-012`, wrote the
`C6` predicate it is judged by, wrote the tests that attack it, and repaired the records under
audit. It cannot verify any of that. The write scope above is deliberately **two files**, neither
of which is under audit: a verifier that can edit the artifact it is auditing is not a verifier.

**The obvious objection is the one to test hardest.** `T-009` changed the criterion that was
failing and the gate now passes. That is the shape of laundering, and the fact that it was ruled
by the human owner and bound by an approval answers the *authority* question without answering the
*evidence* question. This task is directed to attack the relation rather than run it — retire a
report with a bare claim and require nothing to be retired; seal the wrong bytes and require a
failure; rewrite a report after sealing it and require the seal to break — because a relation
observed only working is indistinguishable from one that cannot fail, which is the defect class
`VER-014` recorded four times and `VER-016` recorded twice more.

**Supersession is this task's to declare, and it must be earned.** `VER-014`, `VER-015` and
`VER-016` all stand unrepaired as records; this report retires them only if it verifies what they
found, and it must seal each one's bytes to do so. If any finding of theirs is not in fact
repaired, this task says so and `C6` stays FAIL.
