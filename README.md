## Read this part first

This repository is a **design and process artifact, not a qualified product.** Two things are
true at once and both matter:

- Every CAD-verifiable property is verified, computed from observed model state, and
  reproducible from a clean clone. 846 tests pass. Every standing check exits 0.
- **Nothing physical has been built or measured.** 91 of the 137 numbered component
  requirements need hardware and none is verified. Four mass figures are `MODEL-PREDICTED` and
  labelled so. See [`PVR-001`](.ai/project/verification/PVR-001_Physical_Verification_Record_And_Test_Matrix.md).

And one defect is open against the design itself. Filing the creepage/clearance drawing trace
that an open item recorded as owed found that **the Support Ring isolation joint does not
close**: `SR-02`, `SR-03` and `SR-04` all fail on frozen dimensions, for one reason — two
sections of `spec/03` compute a flange gap as empty while a third puts a 6.00 mm grounded ring
inside it. It is ruled, its remedy is computed, and it is **deliberately not implemented here**
because implementing it is a specification re-baseline. Do not build to this baseline.

## Architecture, in one screen

```
  spec/**  (frozen, hash-registered)
     |
     |  requirements  ->  parameter master  ->  design solution
     v
  src/aief_cad  ------- commands ------->  cad/bridge/queue/  ---.
                                                                  |
  Fusion 360 + fusion_addin/AIEF_CAD_Bridge  <---------------------'
     |                                                            
     |  OBSERVED model state (never the command's own claim)      
     v                                                            
  cad/bridge/obs/  ->  cad/runs/<run>/run.json   (tracked evidence)
     |
     v
  verification  ->  cad/runs/SYSTEM_INTERFACES.json, FINAL_SYSTEM_VERIFICATION.json
     |
     v
  drawings/generate.py  ->  SVG + PDF + provenance sidecar per dimension
  src/sedep/bom         ->  indentured BOM, cross-checked four ways
```

**The rule that shapes all of it: a CAD operation is not evidence that it worked.** Every
acceptance reads the model back out of Fusion — extents, volume, mass, material, feature list —
and compares against the requirement. The file queue is the transport; `cad/runs/**/run.json`
is the record, and it is tracked, including the failures.

### CAD automation

`fusion_addin/AIEF_CAD_Bridge/` is a Fusion 360 add-in that polls a file queue, executes one
operation, and writes back what it *observed*. `src/aief_cad/` drives it: requirements are
compiled to a design solution, the solution to a command sequence, the sequence executed, and
the resulting model verified. A document is **saved only on a verified PASS**; a failed attempt
is discarded or reverted, which is why the tree carries no blank orphan designs
(`cad/DOCUMENT_LIFECYCLE.md`).

### Agent architecture

Five universal roles plus four `mechanical` and three `software` roles, each with a contract
declaring responsibilities, allowed and forbidden actions, escalation rules and duty conflicts
(`.ai/core/agents/`). The constraint that does the work is **LAW-05: no role verifies its own
output.** Independent QA runs in a cold context that reconstructs every fact from the
repository — and it is not decorative: the most recent round returned **NOT CLEARED** and found
a blocking defect in a ruling that had passed 799 tests.

### Verification architecture

Nothing in this repository is believed because a document says it. Every property that matters
has a standing check that computes it, and the checks are attacked by tests that construct the
defect and require failure:

| Check | Property |
|---|---|
| `python -m aief_gate` | The `LC-M04-EXIT` criteria `C1`–`C7`, from the ECR records directly |
| `python -m aief_clearance` | `spec/00` §3.2 feature clearance, pair by pair |
| `python -m aief_params check` | The 105-parameter CAD master against the package |
| `python -m aief_approval verify` | Approval-chain integrity under LAW-10 |
| `python -m aief_deliverables` | The 61 deliverables against their register, both directions |
| `python -m aief_analysis` | `SR-07`/`AP-08` loads and the `SR-02/03/04` insulation trace |
| `python -m aief_stage6` | The framework's own release build; boot step B2a |

Four defect classes went unnoticed for many sessions, and every one was **a declared property
with no standing check**. That is the lesson the repository is organised around.

## Reproducing this

```bash
git clone https://github.com/Raar1999/SEWCP_Master_Assembly.git
cd SEWCP_Master_Assembly
python -m venv .venv && . .venv/Scripts/activate     # Windows; use bin/activate on POSIX
pip install -r requirements.txt

PYTHONPATH=src python -m aief_gate            # LC-M04 CAD-READY: YES, exit 0
PYTHONPATH=src python -m aief_clearance       # CLEARANCE OK
PYTHONPATH=src python -m aief_deliverables    # DELIVERABLES OK - 61 registered, 61 reproduce
PYTHONPATH=src python -m aief_approval verify # APPROVAL CHAINS OK
PYTHONPATH=src python -m pytest tests/ -q     # 846 passed
PYTHONPATH=src python -m aief_analysis        # EXITS 1 BY DESIGN - see below
```

**`aief_analysis` exits 1 and is meant to.** It files the `SR-03`/`SR-04` trace, and the trace
does not close. A check reporting PASS on `ECR-D-016` would be the defect, not the finding.

**What a clone cannot reproduce.** The Fusion designs live in Autodesk cloud versioning, so
`cad/` regeneration needs Fusion 360 with the add-in installed. The tokenizer artifacts the
Stage 6 budget measurement pins are not tracked, so seven `needs_artifacts` tests skip on a
fresh clone. Everything else — every gate, every digest, every drawing, the whole test suite —
runs offline.

## Repository policy

Binding, in force now:

- **No AI attribution** in any commit, file, or document.
- **No `Co-authored-by`** trailers.
- **Git author information is never modified.**
- `spec/` is frozen; defects are raised as an ECR, never edited in place.

## Provenance

The engineering work in this repository — specification, CAD, drawings, analysis, the framework
and its tooling — was produced by an AI agent under human owner authority, with decision
authority delegated for specified runs and every delegated decision recorded as such in
[`.ai/project/decisions/`](.ai/project/decisions/). Human approvals and delegated decisions are
distinguished everywhere they appear, and **a delegated decision is never recorded as a human
approval.** Where a governing rule requires a genuinely independent party — LAW-05 —
independence is supplied by a cold-context session or the item stays open. `ECR-D-014` is open
for exactly that reason.
